## 0. 结论先行

现有项目的**设计底座其实是对的**：`index.css` 里的分层色板（canvas / sidebar / surface 靠明度差建层级）、深墨色主按钮、克制的语义色、6px/8px 圆角约定、`PageHeader` / `SectionHeader` / `EmptyState` 三个公共组件 —— 这套东西已经非常接近 Apple × Linear 的方向。

**问题不在"没有规范"，在"规范没有被执行到底"**：

| 量化证据 | 实测 |
|---|---|
| 任意像素字号 | **8 档**：10 / 11 / 12 / 13 / 14 / 15 / 18 / 22px（**其中只有 10px 那 15 处是可读性问题**，其余是层级问题） |
| 与 Tailwind 标准名并存 | `text-[12px]`×99 与 `text-xs`×79 表达**同一个值**（只影响可维护性，不影响视觉） |
| 圆角档位 | 6px×27 / 8px×40 / 4px×9 / full×18 → **4 档 + full** |
| 页面纵向内边距 | `py-2/3/4/5/6/8/10/12` **8 种**，另有 `p-6 md:p-8` |
| 内容列宽度（实测 1600px） | **768 / 896 / 1167 / 1336 四档**，其中 768 与 896 的差异没有语义 |
| 公共 `PageHeader` 采用率 | **3 / 10 页**（仅 my、insights、external-analysis） |
| 手写空状态 | `还没有/暂无/没有可` 文案 **29 处** + `border-dashed` 容器 **7 处** |
| 原生控件混用 | `type="checkbox"` **4 处**（write / material-picker / external-analysis） |

所以本轮的思路是 **"收口"而不是"重新设计"**：把已有规范补齐、把公共组件推广到全部页面、把 8 档字号砍到 5 档。预期收益集中、风险低、不触碰任何业务逻辑。

## 2. 现有 UI 问题清单（按页面，逐条对应截图与代码）

### 2.1 跨页面共性问题（影响面最大，优先修）

**P1｜内容列宽度在不同页面之间不统一（**不是**"右侧大片空白"）**

> **更正**：上一版把这里写成"内容被挤在左侧、右侧 40% 空白"，那是看图的错觉。
> 本轮补了**实测布局**（写进 `task07_audit/manifest.json`），1600px 视口、可用区 1384px 下的真实数据是：

| 页面 | 内容列宽 | 左留白 | 右留白 |
|---|---|---|---|
| 我的 / 作者 / 风格档案 / 外部分析 | **896** | 244 | 244 |
| 批量导入 / 导入记录 | **768** | 308 | 308 |
| 作者主页 / 跨作者洞察 | **1336** | 24 | 24 |
| 写作 | **1167** | 24 | 193 |

- **留白是左右对称的**（244/244、308/308），不存在"右侧空一大块"
- 真正的问题是：**同一款 App 里内容列宽横跨 768 / 896 / 1167 / 1336 四档，而且这个差异没有语义** —— 768 与 896 只差 128px，说不出为什么「批量导入」要比「我的」窄
- 代码：`mine/style/authors/external-analysis` 用 `mx-auto max-w-4xl`（896px），`import/imports` 用 `max-w-3xl`（768px），`insights/author-detail` 用 `max-w-3xl` 但外层 wrapper 满宽（所以实测 1336），`write/library` 完全不设限
- **结论修正**：不要全站统一到一个 `max-w-[880px]`。按**页面类型**分两档（见 §3.3），且只动真正不一致的那两页

**P2｜页面标题三套写法**
- 证据：`01_我的`（22px）vs `02_写作业_我的创作`（**14px**）vs `07_内容库`（**无标题**）
- 代码：`components/common.tsx:136 PageHeader` 是唯一正确出口，但只有 3 页用它；`authors:108`、`import:271`、`imports:97`、`style:131`、`author-detail:298` 各自手抄同一串 class；`write.tsx:753` 用 `text-sm font-medium`；`library.tsx` 干脆没有 h1

**P3｜字号体系失控**
- 8 档任意像素 + Tailwind 标准名并存（见 §0 表）
- `text-[10px]` ×15 处低于中文可读下限
- 同一页内 `text-[11px]` / `text-[12px]` / `text-xs` / `text-sm` 混用（例：`09_作者.png` 的 "14 帖 14 已分析" 与右侧图标按钮）

**P4｜空状态三种形态，且有无按钮不一致**
- 证据：`01_我的.png` 有两个"虚线框内套虚线框"的空状态；`02_写作业_我的创作.png` 右侧是居中图标+文案（无按钮）；`06_写作_三候选.png` 右侧同样是空状态但**左对齐且无图标**
- 代码：`common.tsx` 有 `EmptyState`，但 29 处 `还没有/暂无` 文案只有少数走它；`border-dashed` 手写 7 处
- **同一页（写作）的两个右栏空状态形态就不一致**，这是最刺眼的一处

**P5｜解释性长文案成为主要视觉元素**
- 证据：`13_批量导入.png`（蓝色非链接说明句）、`14_外部分析.png`（面板里大段 11px 灰字）、`03_写作_对标改写`（素材作者下方 2 行说明）、`10_作者主页.png`（KPI 下方一段系统说明）
- 这类文案内容本身必要，但**当前以正文权重出现**，把界面读起来像说明书。需要降级为"帮助提示"形态（更小、更弱、可折叠，或者移到 tooltip）

**P6｜原生控件与自定义控件混用**
- 证据：`04_写作_对标改写_随机素材未抽取.png` 的「未改写优先」是原生蓝勾选框；`14_外部分析.png` 的「覆盖已有分析」同理

**P7｜"重要操作"按钮重复出现**
- 证据：`01_我的.png`「导入 CSV」在区块头 + 空状态各一个；`06_写作_三候选.png` 生成入口曾有同类问题（任务 06 已修单稿侧）

## 3. 统一视觉规范初稿

### 3.1 处理原则

| 层级 | 手段 |
|---|---|
| **全局公共规范**（改 token / 改公共组件即可全覆盖） | 字号阶梯、间距节奏、圆角、页面容器、页头、区块头、空状态、加载态、反馈 |
| **页面单独处理**（必须逐页改） | 写作页左右分栏与动作条、内容库三栏密度、风格档案的信息重排、作者主页 KPI 区 |

### 3.2 字号：目标是可读性、层级与一致性，不是"把档位数砍掉"

**先把目标摆正**（本版修正）：

- ❌ 不以"消灭 `text-xs` / `text-sm`"为目标。它们与 `text-[12px]` / `text-[14px]` 是**同一个值**，混用只影响可维护性，**不影响视觉**。
- ❌ 不以"把 8 档砍成 5 档"为目标。**11 与 12 的区别在密集工具界面里是有意义的**（元信息 vs 控件文字），强行合并会丢层级。
- ✅ 真正的目标是三件事：**可读性**（消除 10px）、**层级**（每类信息在每页都用同一档）、**一致性**（同类信息跨页一致）。

**要修的只有两类（都能给出具体处数）：**

| 问题 | 处数 | 处理 |
|---|---|---|
| `text-[10px]` 低于中文可读下限 | 15 处 | **提到 11px**（这是唯一的硬性可读性问题） |
| `text-[14px]` 与 13/15 无法区分 | 2 处 | 并入 13px 或 15px |
| `text-[18px]` 孤立值 | 1 处 | 并入 15px 或 22px |
| 写作页标题 14px 与全站 22px 不一致 | 1 处 | 见 P2，属层级问题不是字号问题 |

**保留的语义层级（现状即基本正确，只是要"用对"）：**

| 语义 | 值 | 用途 | 备注 |
|---|---|---|---|
| display | 22px / 600 | 页面标题（每页唯一） | 已有，需推广到全部 10 页 |
| title | 15px / 600 | 区块标题 | 已有（`SectionHeader`） |
| body | 13px / 400 | 主要可读文本、列表主文、表单值 | 已有 |
| label | 12px / 400~500 | 控件文字、按钮、次要信息 | 已有 |
| caption | 11px / 400 | 元信息（时间/计数/标签） | **下限，不再往下** |

**写法统一（低优先，随页面改造顺手做）**：同一页面内不要 `text-xs` 与 `text-[12px]` 并存。**不做全站批量替换** —— 那会把一次视觉改造变成一次高风险的全库 diff。

### 3.3 间距与栅格

- **页面纵向内边距**：统一 `px-6 py-6`（当前有 8 种）；窄窗口（<768px）降到 `px-4 py-5`
- **区块间距**：区块之间 `space-y-8`；区块内元素 `space-y-3`；不在页面里出现一次性 magic number
- **页面容器**（解决 P1）——按**页面类型**分两档，不是全站一刀切：

  | 类型 | 判据（来自实测） | 页面 | 容器 |
  |---|---|---|---|
  | **阅读 / 表单页** | 单列，内容以文字与表单为主，内容列 ≤ 896 | 我的、作者、风格档案、批量导入、导入记录、外部分析、跨作者洞察 | **收窄列**：统一到 **896px**（`mx-auto` 居中） |
  | **数据工作台** | 多列，内容以列表与编辑区为主 | 写作、内容库、作者主页 | **满宽** + 内部栅格，**不收窄** |

  - **只动 2 页**：批量导入、导入记录从 768 → 896。其余阅读页已是 896，不必改。
  - **不采用**全站 `max-w-[880px]`：那会同时改掉 8 个页面，把一个"两页对齐"的小修变成全站布局地震。
  - 写作页 1600px 下 1167 宽 + 右留白 193，是它左右分栏的正常特征（stage 比例控制），**不是缺陷**，不动。
  - 作者主页 / 洞察实测 1336（几乎满宽），是外层 wrapper 满宽所致；它们**属于工作台/统计类**，保持满宽即可 —— 上一版把它们归到"要收窄"是错的。

### 3.4 圆角 / 描边 / 阴影

- 圆角**只用三档**：`rounded`（6px，控件）/ `rounded-lg`（8px，面板）/ `rounded-full`（仅头像与进度条）
  - 废弃 `rounded-sm`(4px) 9 处、`rounded-[4px]` 1 处
- 描边：外框一律 `border-border`，内部细分隔一律 `border-divider`；**禁止嵌套两层虚线框**
- 阴影：只允许 `shadow-popover` / `shadow-dialog`（浮层）；**平面内容不加阴影**，层级靠 `canvas → sidebar → surface` 明度差

### 3.5 控件规范

| 控件 | 规范 |
|---|---|
| Button | 三档：primary（深墨底）/ outline（描边）/ ghost（纯文字）。高度只保留 `h-8`（密集工具栏）与 `h-9`（常规）。**全站同一动作只用一种变体** |
| Input / Textarea / Select | 统一 `h-8` + `rounded` + `bg-canvas` + focus `border-brand`；placeholder 用 `text-tertiary` |
| Checkbox / Switch | **新增一个 `ui/checkbox.tsx`**（6px 圆角、选中态用 `foreground` 深色而非浏览器蓝），替换 4 处原生控件 |
| Badge / Chip | 保留 `Badge` 现有变体；列表行内**最多 2 个彩色标签**，其余降为 `text-tertiary` 文本（修 P4 的色彩噪音） |
| 弹窗 / 抽屉 | 保留 Radix 实现；统一标题 15px/600、内容 13px、底部动作右对齐、`shadow-dialog` |

### 3.6 状态与反馈

| 状态 | 规范 |
|---|---|
| 空状态 | **唯一出口 `common.tsx EmptyState`**：图标 40px 圆形描边 + 15px 标题 + 13px 说明 + **至多一个**动作。全站对齐方式统一为**居中**（修 P4） |
| 加载态 | 列表/面板首次加载用 `Skeleton` 骨架（组件已存在，推广使用）；按钮内联用 14px spinner；**禁用按钮 + spinner 不并存** |
| 错误态 | 行内 `text-danger` + 可重试按钮；不用 toast 承载可恢复错误（toast 只用于一次性成功/失败通知） |
| 成功反馈 | 页面内持久标记（如"✓ 已保存"）+ 可选 toast；不依赖 toast 作为唯一反馈 |
| 悬停/选中 | hover = `bg-hover`；selected = `bg-selected` + `font-medium`；focus-visible 才显示 ring（现有行为保留） |

### 3.7 密度与宽度适配

- **最低支持宽度 1080px**；<1080px 时侧栏折叠为图标条（当前 `md:flex` 是断点，需补一个 `<lg` 的图标态）
- 列表行高统一：密集列表 `h-14`，宽松列表 `h-16`；不再出现 60px 行 + 12px 主文 的失衡
- **所有 `flex` 行内文本必须带 `min-w-0` + `truncate` 或 `flex-1`，动作按钮组必须 `shrink-0`** —— 这条直接修 `N2` 的"单字竖排"缺陷
