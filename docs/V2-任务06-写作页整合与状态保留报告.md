## 1. 第一步：状态为什么会丢

`WritePage` 挂在 `<Route path="write">` / `<Route path="write/:id">` 上（`App.tsx:28-29`）。
用户点「内容库」时路由切走，React Router **卸载**整个页面组件；
页面里 22 个 `useState` 全部归零 —— 主题、素材、三候选、改了一半的编辑稿一起消失。
返回时是**重新挂载**，不是恢复。

现有四种模式各自的职责（改造前）：

| 旧模式 | 做什么 | 生成路径 | 出口 |
|---|---|---|---|
| 灵感起稿 `idea` | 只有想法，要一版起点 | `topic` / `topic_author` | 单稿 |
| 成稿收录 `final` | 自己写完了，只保存 | 无 AI | 收录 |
| 作者起稿 `author` | 只选参考作者，AI 自主选题 | `author_auto` | 三候选 |
| 对标改写 `benchmark` | 别人的内容当素材 | `rewrite` / `rewrite_author` | 三候选 |

## 2. 页面整合

### 2.1 四模式 → 两入口

```
我的创作 = 灵感起稿 + 成稿收录 + 作者起稿
对标改写 = 对标改写（不变）
```

合并的关键是：**旧模式之间的差别只是「手里有什么」，不是三个不同页面**。
所以用「入口 + 有没有输入」推导生成形态，不再把形态写死成标签：

```ts
const genMode: GenMode =
  entry === "benchmark" ? "benchmark"      // 文本是原帖
  : hasText            ? "idea"            // 文本是主题 / 灵感
  :                      "author"          // 没文本 → AI 自主选题
```

**04-C 的五条创作路径一条没少**，且都有断言（见 §4 场景 D）：
`rewrite` / `rewrite_author`（对标改写）、`topic` / `topic_author`（我的创作 + 文本）、
`author_auto`（我的创作 + 无文本 + 参考作者）。

### 2.2 「我的创作」支持的五件事

| 能力 | 入口方式 |
|---|---|
| 输入主题/想法让 AI 创作 | 写文本 → 「生成初稿」 |
| 选参考作者 + 主题创作 | 写文本 + 选参考作者 → 生成 |
| 不输主题、只选作者 → AI 自主选题 | 什么都不写 + 选参考作者 → 生成 |
| 自己写完直接保存 | 写文本 → 「保存原文」 |
| 保存灵感不当成成熟风格样本 | 「保存原文为」旁边的「成稿 / 灵感」切换 |

「成稿 / 灵感」只在**保存操作附近**出现（一行 Segmented + 一句说明），
没有新建三个子页面，也没有第二套保存流程。

**单稿、三候选、编辑功能全部保留**：我的创作的动作条上同时有
「生成初稿」和「生成 3 个候选」；对标改写仍是三候选。

### 2.3 精简控件

- 删除左上角「返回内容库」箭头（全局导航里本来就有「内容库」，页内再放一个是重复）。
  断言方式特意限定在**顶栏范围内**查 `a[href="/library"]` —— 全页搜会被导航项误命中。
- 删除右侧空状态里重复的「生成初稿」按钮；空状态只留一句指路文案。
  断言：页面上「生成初稿」按钮**恰好 1 个**。
- 保留左侧动作条作为唯一的主要生成操作区。
- 生成中 / 已生成 / 编辑中 / 已保存状态原样保留（`还没有初稿` / `正在生成初稿…` /
  `已编辑` / `✓ 已保存到我的内容` + 修改幅度）。

## 3. 状态保留与 × 清空

### 3.1 做法：模块级内存单例 + `useSyncExternalStore`

新增 `frontend/src/lib/write-session.ts`：

```ts
const [draft, setDraft] = useWriteField("draft")   // 形状与 useState 一致
```

- 值存在**模块级单例**里。模块在应用运行期间只加载一次 → 只要不刷新页面状态就一直在
  （刷新 = 重新加载模块 = 归零，正好符合「只要求应用运行期间保留」）。
- `useSyncExternalStore` 订阅，整份 `session` 按字段替换引用 → 判等可靠。
- **没有**新增数据库草稿表、自动保存流程或草稿管理器。

做成 hook 而不是让页面直接读写单例，是为了**结构上防漏**：
漏一个字段的写法是「把 `useState` 写回去」，而那个改动在类型与命名上都看得出来；
逐字面上不存在「忘了把它加进持久化列表」这种漏法。

**进会话的**：入口、主题/原帖/手写正文、编辑稿、AI 基线、rewrite、候选、已采用 key、
素材与作者、参考作者策略、保存身份、随机素材的范围/已看记录/抽到的素材、预填标记。

**不进会话的**（每次挂载重新取）：
`generating` / `saving` / `loading` / `generatingCandidates`、两个选择器弹窗的开合、
画像与跨作者规律的异步读取结果 —— 它们不是「现场」，持久化只会造成
「回来后卡在正在生成中」这类假象。有一条测试专门锁这个字段边界。

### 3.2 不让迟到的请求覆盖已恢复的内容

两条守卫：

1. **预填只做一次**：`sourceId` 只在第一次带该 id 挂载时拉取
   （`prefilledContentId` 记住做过哪一条）。否则「切走再回来」会被这次请求
   覆盖掉已经恢复的现场。
2. **`epoch` 代次**：`× 清空` / 切换入口都会让 `epoch + 1`（只增不减）。
   生成、抽素材、保存这些异步动作在发请求前记下 epoch，响应回来先比对 ——
   对不上就整段丢弃（不 setState、不碰 loading）。随机素材面板同时保留
   任务 05 的 token 守卫，两道一起用。

### 3.3 × 清空

顶栏右上角的 ×（带 tooltip 与 `aria-label`）。点击后走
`resetWriteSession()` → 回到**当前入口**的空白初始态：输入、候选、编辑稿、
素材、参考作者、随机素材现场全部清空；`entry` 保持不变（用户清空是为了马上写下一条，
不是要换入口）。**不动内容库里任何已保存的数据。**

「跳转」与「×」是两种明确不同的行为：
跳转什么都不动、回来原样恢复；× 主动丢弃。没有草稿列表、没有恢复弹窗、没有多级确认。

判定「是否为空」用逐字段比对（`isWriteSessionPristine()`），而不是列几个字段 ——
「只抽了素材、还没写字」也算做过事，漏判会让 × 看起来坏了。

> 踩坑记录：`Object.is([], [])` 是 `false`，初始态里的空数组每次都是新实例，
> 会把「全新现场」误判成「做过事」。已改为数组按长度 + 逐项比较。

### 场景 D｜创作与保存 ✅

| 方式 | 浏览器断言 | 数据库断言 |
|---|---|---|
| 手写原创 → 成稿 | 默认选中「成稿」 | `source=mine`、`provenance=human_original`、`style_eligible=1`、`analysis_state=unprocessed` |
| 个人灵感 | 切到「灵感」后保存 | `source=mine`、`provenance=human_original`、`style_eligible=0` |
| 主题生成（无作者） | 请求 `creation_path=topic` | — |
| 主题 + 作者 | 请求 `creation_path=topic_author`，带 `reference_author_id=1` | — |
| 仅作者自主选题 | 请求 `creation_path=author_auto`，**不带** `source_text` | — |
| 原帖改写 | 请求 `creation_path=rewrite`，带 `source_content_id` | — |
| AI 候选采用 → 编辑 → 保存 | 编辑生效、保存成功 | `source=mine`、`provenance=ai_assisted`、`ai_draft` 基线完整保留、`final_text` 是人工终稿、`edit_ratio=0.2963`、`edit_distance=16`、`is_saved_as_mine=1` |

- AI 辅助稿的 `ai_draft` 基线与最终正文都保留，修改指标真实算出。
- 保存**不自动调用 ANALYSIS**（四条记录 `analysis_state` 全为 `unprocessed`）。
- 「未修改直接保存的 AI 稿仍属 AI 辅助」这一条由既有回归锁着
  （`test_save_without_edit_keeps_ai_assisted`），本轮未改动该链路。

### 场景 E｜页面控件 ✅

- 顶栏内无 `a[href="/library"]`（返回箭头已删）。
