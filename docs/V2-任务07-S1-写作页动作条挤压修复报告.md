六种组合里三种被挤压，其中 1100px 的"我的创作"最严重（12px 宽、18 行）。

## 2. 根因

`write.tsx:1114` 的容器是：

```jsx
<div className="flex items-center justify-between gap-2">
  <span className="text-[12px] tabular-nums text-text-tertiary">…提示…</span>
  <div className="flex items-center gap-2">…按钮…</div>
</div>
```

三个问题叠加：

1. **提示没有 `min-w-0` 之外的任何宽度策略，也没有换行许可** —— flex item 默认
   `min-width: auto`，文字项可以被挤到远小于内容宽度（CJK 任意两字之间都可断行），
   于是逐字换行；
2. **按钮组没有 `shrink-0`** —— 它自己也会被压缩（本轮实测尚未到那一步，但迟早）；
3. **容器不允许换行** —— 放不下时唯一的出路就是把提示压扁。

## 3. 修复（`write.tsx`，一个块，纯 class）

```jsx
<div className="flex flex-wrap items-center justify-between gap-x-4 gap-y-1.5">
  <span className="min-w-0 grow text-[12px] leading-snug tabular-nums text-text-tertiary">…</span>
  <div className="flex shrink-0 flex-wrap items-center justify-end gap-2">…按钮…</div>
</div>
```

| 改动 | 作用 |
|---|---|
| 容器 + `flex-wrap` | 放不下时按钮整组换到下一行（`justify-end` 保证右对齐），提示独占一行 |
| 提示 + `min-w-0 grow` | 占满剩余宽度，按正常行高折行，不再逐字断行 |
| 按钮组 + `shrink-0` | 按钮自身永不变形；必要时在组内换行 |

**关键细节：用 `grow` 而不是 `flex-1`。**
第一版修复用了 `flex-1`（= `flex: 1 1 0%`，basis 为 0），结果"我的创作 1100"修好了、
"对标改写 1100"依旧是 3 行 —— 因为 basis 为 0 会让 flex-wrap 的**换行判定认为永远放得下**，
于是换行从未触发，提示只分到剩下的 101px。`grow` 保留 `basis: auto`（提示的真实宽度），
换行计算才把提示算进去，按钮组才会真的换行。这个坑已写进代码注释。

**没有改动**：按钮的出现条件、`onClick`、`disabled` 逻辑、文案内容、
以及动作条上方「保存原文为 成稿/灵感」那一行（它已有 `flex-wrap`，实测在 820px 下正常折行）。
