## 1. 三处问题的确认与修复（均在 `frontend/src/pages/library.tsx`）

### ① 列表加载 effect 缺 `eligibleFilter` 依赖

「参与 / 不参与风格学习」切换后只有 facets 重查，列表不重查。
依赖数组补上 `eligibleFilter`：

```ts
}, [view, sourceFilter, debouncedQ, tags, topic, type, author, batchFilter,
    eligibleFilter, reloadKey])
```

### ② `activeFilterCount` 漏算三类筛选

原来只算 `tags + topic + type`，导致**只选作者 / 批次 / 风格学习**时
已选筛选条和「清空」按钮都不出现。补齐：

```ts
const activeFilterCount =
  tags.length + (topic ? 1 : 0) + (type ? 1 : 0) +
  (author ? 1 : 0) + (batchFilter ? 1 : 0) +
  (eligibleFilter !== undefined ? 1 : 0)
```

同时 `clearFilters` 从只清 3 项补齐为清全部 6 项（tags / topic / type /
author / batchFilter / eligibleFilter）。

### ③ 已选作者 chip 显示 display_name

`作者：${author}`（username）→ `作者：${authorNames[author] ?? author}`。
`authorNames` 是 S6 已有的 `username → display_name` 映射；**API 参数仍是 username**
（`setAuthor(null)` 只做清除，过滤逻辑不变）。

## 5. 补充验收（最终验收追加项）：三类筛选同时生效 + 清空

> 应验收要求补齐。此前批次筛选经 URL 注入后会丢失同页已选的作者与风格学习条件，
> 三类"同时生效"未被实际验证过。本节在同一页面会话内完成全流程验证。

### 前置（经 UI 完整导入流程构造数据）
- 通过导入页上传 `s5-<tag>.json`（2 条帖子，metadata 带 `author_username: "wangchangfu"`），
  来源选「我的」→ 导入成功（toast「已导入 2 条」）
- mine 来源默认 `style_eligible=1`，作者归属解析到既有作者王长富
- 新批次 `remaining = 2` ✓

### 验证步骤与断言（同一页面会话内）
1. 带 `?import_batch_id=<新批次>` 进入内容库
2. 同页点「参与」→ 请求带 `style_eligible=true` + `import_batch_id`
3. 同页点作者 chip「王长富」→ **同一次 `/api/contents` 请求同时携带**：
   `author_username=wangchangfu & style_eligible=true & import_batch_id=<id>`
4. 已选筛选条同时显示 3 枚：`作者：王长富`、`批次：<id 前 8 位>`、`风格学习：参与`
5. **三类交集总数 = 2**（恰好是导入的 2 条；王长富其它内容因不在该批次被排除）
6. 切「不参与」→ 交集 = 0（导入的 2 条都是参与）
7. 点「清空」→ **三个参数全部消失**（`author_username` / `style_eligible` / `import_batch_id` 均不在请求中）、
   已选筛选条全部消失、「清空」按钮隐藏、列表恢复全量

**结论：三类筛选可同时生效、同请求携带、结果正确、可一键清除。未发现真实缺陷，产品代码零改动**
（`library.tsx` sha256 `85f421996174885d`，与上一轮修复后一致；仅扩充了验证脚本）。
