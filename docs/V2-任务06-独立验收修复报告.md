## 1. 三处问题的确认（源码层）

| # | 现象 | 根因 |
|---|---|---|
| 1 | `/write/:id` 切页再回同一地址 → 永久转圈 | `useState(Boolean(sourceId))` 初值恒为 `true`，而 effect 因「已预填过」提前 `return`，`setLoading(false)` 永远不执行 |
| 2 | `/write/:id` 点 × 后原帖被填回来 | `prefilledContentId` 放在**会话**里 → `resetWriteSession()` / `clearWriteSession()` 把它一起清掉 → 它又是 effect 的依赖 → effect 重新触发 → 重新拉取 |
| 3 | 采用候选的迟到响应写回编辑稿 | `adoptCandidate()` 是异步的，但没有任何代次守卫；请求在途时点 × / 切入口，旧响应照样 `setRewrite / setDraft / setAiDraft / setAdoptedKey` |

## 2. 修复

### 2.1 把「URL 素材簿记」从创作现场里拆出来（问题 1 + 2）

新增模块级簿记（与 `epoch` 并列，**不在** `WriteSession` 里）：

```ts
let handledSourceId: number | null = null
export function getHandledSourceId(): number | null
export function markSourceHandled(id: number | null): void
export function shouldLoadSource(sourceId, handledId): boolean
```

`shouldLoadSource()` 是**唯一**的判据，同时决定两件事：

```ts
const [loading, setLoading] = useState(() =>
  shouldLoadSource(sourceId, getHandledSourceId())   // 初值 = 这次到底会不会去拉
)
...
useEffect(() => {
  if (!shouldLoadSource(sourceId, getHandledSourceId())) {
    setLoading(false)     // 恢复现场这条路径：不发请求，也绝不留加载态
    return
  }
  ... 拉取成功后 markSourceHandled(sourceId)
}, [sourceId, ...setters])
```

**为什么簿记不能放会话里**：× 与切换入口都要清空创作现场，而它们不该清掉
「这个 id 我已经处理过」这件事。放进去就会出现「清掉 → effect 触发 → 又填回来」。

**为什么簿记不能再当 effect 依赖**：否则 × 之后（组件并未卸载）effect 会立刻重跑。
现在依赖只剩 `sourceId` 与几个稳定的 setter —— 停留期间不会因为会话变化而重跑。

于是三种情形各归各位：

| 情形 | 行为 |
|---|---|
| 第一次来到 `/write/123` | 未处理过 → 拉取 + 预填 + 标记 |
| 切页再回同一地址（含浏览器后退、内容库再进同一条） | 已处理过 → **不发请求、不显示加载态**，现场原样恢复 |
| 点 × 之后（原地 / 切走再回来 / 切换入口） | 已处理过 → **不因 URL 把原帖填回来** |
| 打开**另一个**素材 id | id 不同 → 正常拉取 |

## 4. 一处需要你知晓的行为

**同一个素材 ID，在一次应用运行期间只会自动预填一次。**

这是「× 清空后不应因当前 URL 自动恢复旧素材」的直接推论：既然 × 之后不能再拉，
就必须记住「这个 id 处理过了」。副作用是：× 之后从内容库再次点进同一条，
不会重新载入（页面是空的），需要**刷新页面**才会重置这个记忆
（刷新会重新加载模块，簿记与会话一起归零 —— 与「刷新后不要求恢复」的约定一致）。

如果你希望「从内容库显式点进来的」总是重新载入，我可以再加一层区分
（例如把「进入来源」带在导航 state 上）——那是额外行为，本轮按验收原文实现。
