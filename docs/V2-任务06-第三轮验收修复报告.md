## 1. 问题一：主动打开新素材没有清掉上一条的创作

### 确认

预填成功的 `.then()` 只写了 `entry` / `sourceContentId` / `sourceText` / 作者字段，
**没有清 `candidates` / `adoptedKey` / `draft` / `rewrite` 等**。
于是编辑素材 A 的候选 B 之后主动打开素材 B，屏幕上会同时存在新素材与旧编辑稿。

### 修复

把「只覆盖几个字段」换成会话模块**唯一**的清空动作，放在 `.then()` 里：

```ts
.then((data) => {
  if (cancelled || !isSameEpoch(epoch)) return
  clearWriteSession("benchmark")   // ← 干净的对标改写现场
  markSourceHandled(sourceId)
  setSourceContentId(sourceId)
  setSourceText(data.raw_text)
  ...
})
```

一次调用同时做到三件事：

1. **清现场** —— 候选、已采用状态、编辑稿、`aiDraft` 基线、`rewrite` 关联记录、
   `saved`、素材链接与作者、随机素材面板的临时状态；
2. **入口落到 `benchmark`** —— 顺带保留了上一轮那条修复（不再需要单独 `setEntry`）；
3. **`epoch` 递增** —— 上一轮所有在途请求（生成 / 采用 / 抽素材）就此作废，
   符合「同时作废上一轮未完成的异步响应」。

**位置刻意放在 `.then()` 里而不是请求前**：只有真的载入成功才清现场 ——
取内容失败时不该把用户手里的东西一起丢掉。

`clearWriteSession` 的 `epoch` 递增放在「校验 `isSameEpoch(epoch)` 之后」是必须的：
如果提前清，这次载入自己的守卫就会失效。

**普通切页返回不受影响**：恢复分支（`setLoading(false); return`）一行都没改，不清现场。

## 2. 问题二：已使用的导航票据可能再次生效

### 确认

`consumedTicket` 与 `handledSourceId` 都只记**最后一个**。于是：

- 打开 A（票据 A）→ 打开 B（票据 B）→ 历史返回 A：票据 A 不再等于「最后一张」→
  被误判成未使用 → 又执行一次主动打开；
- 即便只修票据，`shouldLoadSource(A, handled = B)` 仍会得出 `A !== B` → 触发重新载入。

两条路都会让**旧 A 的原文覆盖当前 B 的写作现场**。

### 修复

两处都从「单个值」改成「集合」：

```ts
const handledSourceIds = new Set<number>()
const consumedTickets = new Set<string>()

export function isFreshMaterialOpen(ticket) { return Boolean(ticket) && !consumedTickets.has(ticket) }
export function shouldLoadSource(sourceId)   { return sourceId !== null && !handledSourceIds.has(sourceId) }
```

修完全部的载入判定就一句话：**只有「没见过的 id」或「没兑现过的新票据」才会拉取**。

| 情形 | 判定 | 结果 |
|---|---|---|
| 首次打开 A | id 未见过 | 拉取 |
| A → B → 历史返回 A | 票据 A 已兑现；且 A 在已处理集合里 | **不拉取**，现场保持 B |
| 再次主动点「改写这条」A | 新票据 | 拉取（无视已处理标记） |
| 普通切页返回 | 两项都不成立 | 不拉取，恢复现场 |
| × 之后停在同一 URL | 同上 | 不拉取 |

StrictMode 处理（`freshOpenRef` 让判定在 effect 双跑下稳定）与 × 清空机制**原样保留**。
