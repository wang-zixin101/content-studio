## 1. 缺陷确认（属实）

`switchMode()` 清空了 `sourceText`、`sourceAuthorId`、`sourceAuthorLabel`，
但**漏掉了 `sourceContentId` 与 `sourceEntry`**。

两个真实后果（与验收描述一致）：

1. **自主选题路径冲突**：对标改写选中内容库素材 → 切到「作者起稿」→
   `sourceText` 已空但 `sourceContentId` 仍在 → 前端按「无素材」推导出 `author_auto`，
   服务端却会按 id 取回原文当作素材 → 与 `author_auto`「不接收素材」冲突，
   `resolve_creation_path()` 直接报错。
2. **新主题错误关联旧素材**：切到「灵感起稿」写下新主题 →
   请求仍带旧 `source_content_id` → 新主题被挂到旧对标素材上，
   且旧素材的 ANALYSIS 会被注入本次 prompt。

`sourceEntry` 残留 "random" 还会让下一次进入对标模式时停在抽素材阶段之外。

## 2. 修复

### 2.1 把素材态收拢成可测的纯函数（`frontend/src/lib/rewrite-flow.ts`）

```ts
export type SourceEntry = "specified" | "random"

export interface SourceSlice {
  sourceText: string
  sourceContentId: number | null
  sourceEntry: SourceEntry
  sourceAuthorId: number | null
  sourceAuthorLabel: string | null
}

export function initialSourceSlice(): SourceSlice
export function resetSourceOnModeSwitch(): SourceSlice   // 切换模式的唯一重置出口
export function hasSourceInput({ sourceText, sourceContentId }): boolean
export function sourceFieldsFor({ sourceText, sourceContentId }): {
  source_text?: string
  source_content_id: number | null
}
```

三个动机：
- `resetSourceOnModeSwitch()` 把「换模式后不得残留旧素材」变成**可断言的纯函数**，
  而不是靠人眼检查 switchMode 里十几行 setState；
- `sourceFieldsFor()` 是生成请求素材字段的**唯一出口**，测试可以直接断言请求体；
- `hasSourceInput()` 补上了一个**二阶缺陷**：前端判定「有没有素材」时只看文本、
  不看 `sourceContentId` —— 而服务端把「只给 id」也当有素材（会取回原文）。两边口径必须一致。

### 2.2 `switchMode()` 整片重置（`frontend/src/pages/write.tsx`）

```ts
const clean = resetSourceOnModeSwitch()
setSourceText(clean.sourceText)
setSourceContentId(clean.sourceContentId)   // ← 旧版漏掉
setSourceEntry(clean.sourceEntry)           // ← 旧版漏掉
setSourceAuthorId(clean.sourceAuthorId)
setSourceAuthorLabel(clean.sourceAuthorLabel)
```

其余清空逻辑不变（`setFixedAuthorId(null)` / `setRefMode("none")` /
`setUseProfile(true)` / 候选与草稿态）。

### 2.3 顺手收敛的第三个泄漏点：`generateDraft` 用的是 `sourceId`

旧版单稿请求写的是 `source_content_id: sourceId` —— 那是 **URL 参数**带来的初始值，
`switchMode()` 永远清不到它。也就是说即使修好了 `sourceContentId`，
从内容页进入（`/write/:id`）再切换模式，单稿请求仍会带旧素材 id。

已改为与三候选共用同一个出口：

```ts
const res = await api.generateDraft({
  ...sourceFieldsFor({ sourceText, sourceContentId }),   // 唯一出口
  ...
})
```

`sourceId` 现在只剩一个职责：首次挂载时预填素材（`useParams` → `getContent`）。

### 2.4 路径判定口径对齐

`creationPath` 的 `hasSource` 由 `Boolean(sourceText.trim())` 改为
`hasSourceInput({ sourceText, sourceContentId })`。
纵深防御意义：即使将来重置函数被改坏、旧 id 真的残留，
「作者起稿 + 有素材」也会被判成 `null`（冲突，拦住）而不是错走 `author_auto`。
