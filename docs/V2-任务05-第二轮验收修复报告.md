## 1. 竞态确认（属实）

`material-picker.tsx` 的 `draw()` 在响应回来时**无条件**落地，`switchRange()` 也不作废在途请求：

```ts
const data = await api.getRandomMaterial({...})
setMaterial(data)                       // ← 不看这次请求还属不属于当前范围
setSeen(addSeen(nextSeen, data.content_id))
} finally {
  setLoading(false)                     // ← 同样无条件
}
```

复现链路：
1. 选「王长富」→ 点「随机抽取」，请求在途；
2. 响应回来前点「老雷」→ `switchRange` 把 `material` 清空、`pool` 改成老雷；
3. 王长富的响应返回 → `setMaterial(王长富的帖子)` → **卡片显示在「老雷」范围下**；
   同时王长富的 `content_id` 混进老雷的 `seen` 列表（后续换一条会凭空少掉一批）。

## 2. 修复

按验收建议的**两条一起做**（互为纵深，各自都很简单）：

### 2.1 忽略已过期请求（核心正确性）

新增纯逻辑 `frontend/src/lib/material-range.ts`：

```ts
export interface DrawSession { latest: number }
export function newDrawSession(): DrawSession
export function beginDraw(session): { session: DrawSession; token: number }
export function invalidateDraws(session): DrawSession      // 切换范围 = 作废全部在途
export function canApplyDraw(session, token): boolean       // 唯一允许落地的条件
export function rangeSwitchDisabled(loading): boolean
```

组件用 `useRef` 持有 session（不该触发渲染），每次抽取领一个递增 token；
**响应、异常、`loading` 三者全部只归最新那次请求管**：

```ts
const begun = beginDraw(drawSession.current)
drawSession.current = begun.session
const token = begun.token
try {
  const data = await api.getRandomMaterial({...})
  if (!canApplyDraw(drawSession.current, token)) return   // 过期 → 整段丢弃
  setMaterial(data); setSeen(...)
} catch (err) {
  if (!canApplyDraw(drawSession.current, token)) return   // 旧范围的错误也不显示
  ...
} finally {
  if (canApplyDraw(drawSession.current, token)) setLoading(false)
}
```

`loading` 也必须被守卫：否则旧请求的 `finally` 会在新请求仍在途时把「正在抽素材…」提前收掉。

`switchRange()` / `restart()` 第一件事就是 `invalidateDraws()`（并顺带收掉 `loading`，
那一次抽取已不属于当前范围）。

### 2.2 抽取期间禁用范围切换（体验 + 加固）

范围行加 `disabled` + `cursor-not-allowed opacity-50` + `title="正在抽素材，请稍候"`。
避免用户点一个「暂时不会有反应」的按钮。

> 诚实标注：**禁用之后，token 守卫在 UI 上不可达**（正常操作不可能在加载中切成另一个范围）。
> 它保留的原因是纵深防御 —— 防的是「将来有人放开禁用」「组件被复用到别处」「同一 tick 内
> 两次派发」这类回归。这不是冗余，但也不该被当成当前唯一的保护来说明。
