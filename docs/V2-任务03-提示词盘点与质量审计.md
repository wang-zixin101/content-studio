### 3.2 P2 ANALYSIS V2 —— 问题清单（最高优先级）

**A1【已证实】字段语义重叠，无任何判别规则**
54 个叶子字段中至少 5 组高度重叠，而 system 只有 **182 字**，未给出任何判别标准：
- `opening_type`（开头方式） vs `rhetorical.hook_mechanism`（开头的抓取机制）
- `tone`（语气） vs `emotion`（主要情绪） vs `microstyle.register`（语体）
- `sentence_style` vs `microstyle.sentence_rhythm` vs `microstyle.sentence_length_pattern` vs `microstyle.fragments_level`（4 个字段都在描述句式/节奏）
- `structure`（箭头链） vs `rhetorical.moves`（修辞动作）
- `stance_engagement.certainty` vs `subjectivity` vs `disagreement_intensity`
- `content_invariants.factual_claims` vs `opinions_or_judgments`

**影响**：这 54 个字段是 Stage 6 / 8 / 9 画像与 Stage 10 策略的**唯一数据源**。同一个字段在不同帖子上取值口径不一致，聚合出的分布就是噪音，画像与策略随之失真。这是全系统**放大系数最高**的缺陷。

**A2【已证实】实时与 Batch 的 max_tokens 不一致（1500 vs 2000）**
- `analyzer.py:75` `max_tokens=1500`
- `batch.py:70` `max_completion_tokens=2000`

59 字段中文 JSON 在 1500 token 下有真实截断风险；截断 → `extract_json()` 失败 → `chat_json` 自动**再打一次模型**（仍然 1500）→ 用户侧表现为慢 + 费用翻倍，且失败原因不可见。

**A3【已证实】内部路径完全不做 spec 校验，内外两套质量标准**
`validate_analysis_v2()` 只服务外部导入（`external_analysis.py`）。实时 / Batch 只走 `normalize_analysis()`，它**宽松到不会失败**：缺字段静默变 `None` / `[]`，类型错了靠 `_s()` / `_as_list()` 兜。这些 `None` 会原样进 `raw_json`，Stage 6 聚合时拿到 `None`。

**A4【已证实】Schema Hint 是伪 JSON，约束不可执行**
`ANALYSIS_SCHEMA_HINT` 不能被 `json.loads()`（`"length_chars": 中文字符数（整数）`）。字段约束（topic 2-8 字、tags 3-6 个、core_viewpoint ≤40 字）全是自然语言软约束，**没有任何校验**。

**A5【已证实】无 few-shot、无输出示例、无字段级不确定处理**
system 只说"只描述文本中真正存在的现象"，但没有告诉模型"信息不足时该填什么"。`must_preserve` 与 `factual_claims`、`evidence_modes` 与 `moves` 的边界全靠模型自己猜。

**A6【推断】开放式自由文本字段导致跨帖不可比**
`hook_mechanism` / `moves` / `evidence_modes` / `closing_function` / `information_density` 全是自由文本。模型每次会用不同措辞描述同一现象 → 画像聚合出的是长尾分布（每个值只出现 1 次）→ `PROFILE_TOP_VALUES=8` 拿不到有意义的 Top N。**建议改为"受控词表 + 允许自由补充"双字段**。

**A7【推断】对极短文本强行填 54 字段必然产生幻觉式推断**
真实语料中位长度仅 **52 字**（159 条 Xporter 导出实测）。52 字要填出"修辞动作 / 论据类型 / 互动装置 / 连词习惯 / 插入语习惯 / 重复习惯……"，模型只能编。应有更强的"信息不足 → null"约束和**字段级置信度**。

**A8【待实验】重测一致性未知**：同一帖跑 3 次，59 个字段的取值一致率没有测过。这是判断该提示词能否支撑画像的**前置指标**。

### 3.3 P3 STYLE V2 —— 问题清单（次高）

**S1【已证实·产物】小样本过度归纳，且低置信度结论照样被当成确定性注入下游**
`data/style_profile_backup_before_delete.json` 中 version 1（`based_on_count=3`）：
- `evidence.confidence = "low"`
- 却产出 **6 条 `signature_patterns`**，其中 **4 条 `classification=VOICE`**，`strength=medium` 的 3 条分别基于 3/3、2/3、3/3 篇
- **3 条 `x_modes` 的 `sample_count` 全为 1** —— 直接违反 `build_style_messages` 额外要求第 1 条"单篇出现一次的现象不要写成规则"

更严重的是：`_build_summary()`（`style_profile.py:280-312`）只取 `voice_summary` + `common_openings/endings/expressions/tones` + `edit_patterns`，**把 `confidence` 与 `uncertain_patterns` 全部丢弃**。于是"3 篇样本归纳出的 low-confidence 结论"以完全确定的语气注入 WRITE 的「全局风格档案」。

**S2【已证实·产物】authorship 硬规则未被遵守**
version 2（`based_on_count=8`）：
- `evidence = {sample_count:8, human_original_count:**0**, ai_assisted_count:**0**, rewrite_pair_count:0, confidence:"medium"}`
- 但仍然产出 **8 条 signature_patterns，其中 6 条 `VOICE`、3 条 `strength=strong`**

`STYLE_SYSTEM` 明确写了"只有 human_original / imported_self 可以作为 high authorship evidence"。8 篇样本 provenance **全部未知**的情况下判 strong VOICE，说明提示词缺少可执行的降级判据（应明确写"provenance 未知 → classification 只能 UNCERTAIN、strength 不得高于 weak"）。

**S3【已证实】注入 WRITE 的风格上下文严重残缺**
`_build_summary()` 只保留 5 类信息，**以下全部丢失**：
`global_voice`（7 维）、`signature_patterns`、`anti_style`（明确要求避免的表达）、`x_modes`（什么场景用什么模式）、`topic_bound_terms`、`uncertain_patterns`、`avg_length`、`long_short_ratio`、`first_person_habit`、`viewpoint_style`、`emotion_profile`、`high_freq_words`。

而 `_WRITE_PERSONALIZED` 段要求模型复制"句长分布、节奏、观点推进、转折、立场强度、读者关系、词汇选择倾向、段落和换行、标点、收尾方式"——**要求的信息有一半根本没传进去**，尤其是 `anti_style`（不该写什么）完全缺失。

**S4【已证实】`style_summary` 与 `style_profile` 二选一注入**
`build_write_messages` 中是 `if style_summary: … elif style_profile: …`，两者永不同时出现。摘要丢了结构化细节，全量 JSON 又太长（`profile_json` 实测约 4–6 KB）。缺一个"关键结构化字段 + 摘要"的混合方案。

**S5【推断】触发门槛与 PERSONALIZED 门槛自相矛盾**
`MIN_CONTENT=3` 允许 3 篇就建档案；而 `personalization` 要求 ≥10 篇且 ≥3 主题 ≥2 类型才进 PERSONALIZED。结果是：**在 COLD_START 阶段就能产出一版"strong VOICE"档案**，而 WRITE 在 COLD_START 下又会硬性清空风格证据（`build_write_messages` 里 `if state == "COLD_START"` 把 examples/style 全设 None）—— 两个模块的保护逻辑互相打架，档案白算。

**S6【推断】`edit_preferences` 长期空缺**
需要 ≥3 对 (AI 初稿, 用户终稿) 才有确定性 `edit_patterns`；当前库里 0 对。此时模型归纳的 `edit_preferences` 会被保留（代码只在 `edit_patterns` 为空时才清空 `frequent_*`），但那是**没有行为证据的推测**，而 prompt 又说了"不要推测用户不喜欢什么"。两者有张力。

**S7【待实验】max_tokens=3000 是否够**（v2 产物完整，暂未观察到截断）。

### 3.4 P1 WRITE V2 —— 问题清单

**W1【已证实·源码 bug】单稿路径永远不注入内容不变量**
- `rewriter.generate_draft`（`rewriter.py:129-131`）取的 `source_analysis = repo.get_analysis(...)`
- `repo.get_analysis`（`repository.py:1740-1756`）**只返回 13 个扁平列，不含 `content_invariants`**
- `build_write_messages`（`prompts.py:377-383`）里 `source_analysis.get("content_invariants")` → **恒为 None**
- 结果：`P1-a` 路径的「内容不变量」区块**从来不会出现**，尽管 `_WRITE_TAIL` 要求"必须保持实体 / 数字 / 时间 / 核心事实 / 观点归属 / 因果关系 / 不确定性"——模型收到了要求，却**收不到事实清单**。
- 对照：`P1-b` 三候选路径专门用 `repo.get_analysis_invariants()` 单独取了（`rewrite_candidates.py:114-118`）。

→ **两条路径上下文不一致，单稿路径存在实质缺陷。这是本轮最明确的、应立刻修的问题。**

**W2【已证实·产物】COLD_START 真实输出含方括号占位符**
Desktop 库 `rewrites.id=1`（model=`mimo-v2.6-pro`，prompt_version=`v2`，state=`COLD_START`）的 `ai_draft`：

```
我去。

[一句话写清楚发生了什么 / 你看到了什么]

愣了好几秒才反应过来。
```

`_WRITE_TAIL` 禁止了"解释 / 汇报 / 代码块 / 初稿如下"，但**没有禁止占位符与模板括号**。单一证据（n=1），但性质严重：用户拿到的是需要填空的模板，不是初稿。建议在禁令里显式加"禁止输出方括号占位符、禁止输出需要用户填空的模板"，并在代码侧加一个占位符检测（`[` + `请` / `什么` / `XXX` 这类模式）作为兜底。

**W3【已证实】`REFERENCE_AUTHOR_PROFILE` 规则在三候选路径永不触发**
`build_candidate_write_messages()` 的签名里**没有** `reference_profile` 参数，所以 `_WRITE_BASE` 中整段"如果提供了 REFERENCE_AUTHOR_PROFILE…"的 6 条规则在 P1-b 出口是**死指令**。参考作者信息在 P1-b 里改由 `strategy_context` + `_WRITE_STRATEGY_RULES` 承载，两套规则措辞不同。

**W4【已证实】9 级证据优先级列表缺少"历史数据规律"这一项**
`_WRITE_BASE` 列了 9 级优先级（用户当前要求 → … → 模型默认习惯），但 `strategy_context`（历史统计规律）**不在列表里**。它在 user 消息里的位置是"内容不变量之后、素材之前"，靠注入顺序暗示优先级 —— 这个机制很脆弱，模型不一定读得出位置含义。

**W5【推断】温度与"内容保真"存在张力**
分析类 0.2、风格类 0.4、写作类 **0.85 / 0.9**。写作任务同时要求"实体 / 数字 / 事实一个都不能改"和"有创造力"，0.85–0.9 偏激进。建议：单稿降到 0.7（保真优先），三候选保留 0.9（差异度优先），并在提示词里加一段**输出前自检清单**（实体/数字/归属是否与素材一致）。

**W6【推断】`_WRITE_TAIL` 的"避免清单"是黑名单式，容易触发过度规避**
列了 10 条"避免"（空洞升华、总结式结尾、客服语气、论文腔、机械三段式、"首先其次最后"、过度解释、强行排比、rule-of-three、机械"不是X而是Y"）。黑名单会同时压制合理用法。更有效的是补**正向结构约束**：X 中文短内容的长度带、换行节奏、信息密度、钩子位置。

**W7【待实验】三候选标签协议稳定性未知**
`<CANDIDATE_A>` / `</CANDIDATE_A>` 严格解析，失败即报错且不重试（设计上正确）。但对 `mimo-v2.6-pro` 的实际成功率没有测过 —— 建议用真实素材连跑 20 次统计解析失败率。

**W8【已证实】示例与样本被硬截断**
`EXAMPLE_CHARS=600`（WRITE 的用户作品）、`SAMPLE_CHARS=800`（STYLE 的样本）。中位 52 字影响不大，但最长 3999 字的帖子会被切掉 85%，模型看到的"用户风格"是被截过的。

### 3.5 跨提示词问题

**X1【已证实】提示词措辞没有任何指纹或测试锁定**
- Schema 有 `ANALYSIS_SCHEMA_HASH`（自动 SHA256，外部导入强校验，不匹配即拒收）
- 但 **prompt 措辞没有指纹**：改了 `ANALYSIS_SYSTEM` 的措辞，`ANALYSIS_PROMPT_VERSION` 仍是 `"v2"`，`schema_hash` 也不变

后果：**同一个 schema_hash 下可以换任意措辞**，外部模型与内部模型可能产出分布完全不同的结果，却共享同一 hash，系统无法察觉。

**X2【已证实】版本记录覆盖不全**
- `rewrites.prompt_version` 只记录 WRITE 版本
- `batch_jobs.prompt_version` 记录 ANALYSIS 版本
- **`style_profile` 表没有 `prompt_version` 列** → 无法追溯某版档案由哪版 STYLE 提示词产出
- `analyses` 表**没有 prompt_version 列**

**X3【已证实】4 个模型槽位默认同一模型**
`model_analysis / model_rewrite / model_style / model_batch` 默认全是 `mimo-v2.6-pro`。配置层已支持拆分，是好事（未来可按任务选模型），但当前没有任何按任务差异化的实测依据。

### 4.3 可引入的科学理论（做成词表与规则，不是让模型"用某理论分析"）

| 理论 | 对应字段 | 怎么用 |
|---|---|---|
| **Hyland 立场与介入（Stance & Engagement, 2005）** | `stance_engagement.*` 全部 10 个字段（hedge / booster / attitude / self-mention / reader-address / engagement devices） | 这套字段**本来就是 Hyland 框架的中文简化版**，但提示词里没点名，模型只能自由发挥。点名后可直接给出各类的标准中文标记词表 |
| **Martin & White 评价理论（Appraisal: affect / judgment / appreciation + graduation）** | `emotion`、`attitude_markers`、`booster_markers`、`hedge_markers`、`disagreement_intensity` | 给情感与态度建立层级词表；graduation（语势分级）直接对应 booster/hedge |
| **Biber 多维语体分析（1988）** | `microstyle.register`、`sentence_rhythm`、`sentence_length_pattern`、`fragments_level` | 把"口语化/书面化"这种二分改成可操作的维度（交互性 vs 信息性、叙述性 vs 论证性） |
| **Cialdini 说服六原则**（互惠 / 承诺一致 / 社会认同 / 喜好 / 权威 / 稀缺） | `rhetorical.hook_mechanism`、`rhetorical.evidence_modes`、`engagement_devices` | 极适合 X 短帖，可直接作为 hook_mechanism 的受控词表骨架 |
| **Loewenstein 信息缺口理论（information gap）** | `rhetorical.hook_mechanism` | "悬念型开头"的可判定定义 |
| **Petty & Cacioppo ELM（中枢路径 / 边缘路径）** | `rhetorical.evidence_modes` | 数据/论证 = 中枢；权威/情绪/从众 = 边缘，给出二分判据 |
| **古典修辞五艺 + 修辞格**（antithesis / hyperbole / anaphora / rhetorical question / tricolon） | `rhetorical.moves`、`microstyle.repetition_habit` | 直接给 moves 建立枚举词表 |
| **情绪效价-唤醒度（valence-arousal 二维）** | `emotion` | 把"平静/激动"这种单维描述改成二维坐标，跨帖可比 |
| **Shannon 信息论（冗余与密度）** | `rhetorical.information_density` | 给"高/中/低信息密度"一个可判定的操作性定义（如：每百字新命题数） |

**传播学 / 心理学引入的边界**：理论要落成**词表与判据**，不要让模型"从传播学角度分析"——那只会让输出更啰嗦且不可比。
