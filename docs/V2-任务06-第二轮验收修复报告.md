## 1. 问题一：从素材进入没有切到「对标改写」

### 确认

`entry` 的会话默认值是 `create`，预填 effect 只写素材字段、**不动 `entry`**。
于是 `genMode` 推导成 `idea`（有文本 → 主题）→ `creation_path=topic`，
原帖被当成"主题"，`source_content_id` 也随之失去了意义。

### 修复

预填成功的同一个 `.then()` 里补一行：

```ts
markSourceHandled(sourceId)
setEntry("benchmark")   // 从素材进入 = 做「对标改写」
```

位置选在这里而不是 effect 开头：**只有真的载入了素材**才切入口，
加载失败时不该把用户从"我的创作"甩到"对标改写"。

`entry` 平时只能经 `switchEntry()` 改（它要连带清空现场）；这里是唯一的例外 ——
它发生在一个刚装载的全新现场上，不存在要清的旧内容（已在代码注释里写明）。

## 2. 问题二：区分「普通返回」与「主动打开」

### 需求

| 操作 | 期望 |
|---|---|
| 普通切页再回来 | 恢复现有写作现场 |
| 点击 × | 清空，不自动恢复 |
| 从内容库点「改写这条」 | **重新载入**指定素材，即使之前打开并清空过同一 ID |

三种情况在路由上**完全相同**（同一个 `/write/:id`），这是难点。

### 为什么不能只靠「已处理过的 id」

上一轮引入的 `handledSourceId`（模块级，× 清不掉）解决了"× 后不恢复"，
但它同时意味着"同一条素材永远不会再自动载入" —— 与"主动打开要重新载入"冲突。

### 最小改动：导航票据

新增一次性票据，由**导航 state** 携带：

```ts
// 内容库侧（content-detail-sheet.tsx）
navigate(`/write/${detail.id}`, {
  state: { openMaterial: { id: detail.id, ticket: newMaterialOpenTicket() } },
})
```

```ts
// write-session.ts
export function isFreshMaterialOpen(ticket): boolean   // 未兑现过 → 新的主动打开
export function markMaterialOpenConsumed(ticket): void // 兑现（幂等）
```

```ts
// write.tsx
const freshOpen = open?.id === sourceId && (… || isFreshMaterialOpen(open.ticket))
if (!freshOpen && !shouldLoadSource(sourceId, getHandledSourceId())) {
  setLoading(false); return          // 恢复现场：不发请求
}
…                                     // 其余情况一律拉取（含"主动重开同一条"）
```

**为什么票据而不是"有没有 state"**：浏览器后退会把同一个 history 条目连同 state
一起带回来。票据兑现过就不再算新打开 —— 后退因此正确地走"恢复现场"。

**StrictMode**：`main.tsx` 开着 `React.StrictMode`，effect 会跑两遍。
判定结果缓存在 `useRef` 里（`freshOpenRef`），第二遍得到同样结论 ——
否则第二遍会走恢复分支、把第一遍的请求取消掉，表现为"永远预填不上"。

状态管理没有重构：仍是同一套会话单例，只是多了一张不参与渲染的票据。

### 4.2 浏览器回归（`verify_task06_fix.mjs`）

覆盖「从内容库打开 `/write/:id`」的完整真实流程
（内容库 → 点一行 → 详情面板 → 「改写这条」→ `/write/:id`）：

```
F1  首次打开：预填 + 不卡加载
    ✓ 入口已自动切到「对标改写」                       ← 本轮问题 1
    ✓ 生成路径正确：creation_path=rewrite，
      source_content_id=19，source_text 是完整原文      ← 本轮问题 1
F2  切到「作者」→ 浏览器后退回同一地址
    ✓ 不卡加载 + 输入现场原样恢复                      ← 普通返回
F3  再次点「改写这条」同一素材
    ✓ 重新载入原素材（覆盖上一次的编辑）                ← 主动打开
F4  点 × 停在同一 URL：1.8 秒内无内容被填回
F4b × 之后切走再回到同一 URL：内容仍为空               ← × 不自动恢复
F5  切换一级入口后同样不得恢复
F7  × 之后再次主动打开同一素材：重新载入 + 落在「对标改写」
F6  采用请求在途时点 × → 放行迟到响应：编辑稿与「已采用」状态都没被写回
```

F3 与 F4b 是**对照**：同样是从 `/write/:id` 进入，普通返回不许恢复、主动打开必须重新载入。
